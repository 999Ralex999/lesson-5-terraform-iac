# Урок 5: Terraform — Infrastructure as Code (IaC) в AWS

## 🎯 Мета проєкту

Навчитися використовувати Terraform для опису інфраструктури як коду, створивши продакшн-подібне середовище в AWS. У проєкті реалізовано:

- Зберігання стану Terraform у S3-бакеті з блокуванням через DynamoDB
- Побудова VPC зі всією необхідною структурою (Public/Private Subnets, NAT Gateway)
- Створення приватного репозиторію в Amazon ECR для зберігання Docker-образів
- Повна автоматизація через модулі та змінні

## 🧩 Опис модулів

### `s3-backend`
- Створює **S3-бакет** для зберігання `terraform.tfstate`
- Вмикає **versioning**
- Створює таблицю **DynamoDB** для блокування стану
- Параметри передаються через змінні
- Результати експортуються через `outputs.tf`

### `vpc`
- Створює **VPC** з CIDR `10.0.0.0/16`
- Додає 3 публічні та 3 приватні підмережі
- Підключає **Internet Gateway** для публічних мереж
- **Elastic IP + NAT Gateway** для приватного виходу в інтернет
- Налаштовує дві маршрутні таблиці: для публічних та приватних мереж
- Прив’язує таблиці до відповідних підмереж

### `ecr`
- Створює **репозиторій в Amazon ECR**
- Вмикає автоматичне сканування образів (опція `scan_on_push`)
- Виводить URL-адресу репозиторію для подальшого використання

## ⚙️ Основні команди Terraform
Клонувати репозиторій:
- terraform init       # Ініціалізація проєкту та підключення до S3 backend
- terraform plan       # Попередній перегляд змін

- terraform destroy    # Повне видалення ресурсів у AWS

## 🧹 Знищення інфраструктури (`terraform destroy`)

Після завершення роботи з інфраструктурою важливо **коректно видалити всі створені ресурси**, щоб уникнути зайвих витрат в AWS.

### 🔧 Команда для знищення:
- terraform destroy

### ✅ Що відбувається під час виконання команди:
Видаляються всі створені ресурси:
- VPC, NAT Gateway, Elastic IP, публічні та приватні підмережі,
- Internet Gateway, Route Tables, S3, DynamoDB, ECR тощо.

### ⚠️ Помилка при знищенні S3 бакету:

BucketNotEmpty: The bucket you tried to delete is not empty.

Причина: бакет має включене versioning, тому його потрібно очистити вручну.

### 🛠️ Що зробити вручну в AWS Console:
1. Очистити бакет (Empty):

- Зайти в S3 → обрати потрібний бакет.

- Натиснути кнопку Empty.

- Ввести permanently delete для підтвердження.

- Переконатись, що всі версії об’єктів видалено.

2. Видалити сам бакет (Delete):

- Натиснути Delete.

- Ввести назву бакету для підтвердження.

Після цього Terraform зможе завершити видалення без помилок,
або ж видалення вважається завершеним вручну.

### 🔐 Перевірка IAM після знищення:
Переконатись, що більше не використовуються Access Keys.

За потреби — видалити IAM-користувача terraform або обмежити його права.
